# MapAble Intelligence Fabric

## Purpose

The Intelligence Fabric is integrated into the existing MapAble application. It is not a separate lab, research dashboard, or prototype. It provides one participant-facing manager agent with specialist Care, Transport, Jobs, Access, Moves, Foods, and AbilityPay agents behind it.

The first vertical slice prepares an accessible journey to a support appointment. It reads the signed-in participant's calendar, optionally reads participant-controlled mobility preferences, proposes transport options, explains the recommendation and uncertainty, and requires explicit confirmation before the existing transport service creates a request.

## Existing architecture retained

- Next.js App Router and existing `/ask` experience
- NextAuth session and permission checks
- Prisma data model and service layer
- Existing calendar, transport, consent, audit, and agent-run services
- Existing Tailwind and UI components
- Existing non-AI transport request flow

## New architecture

```text
/ask accessible interface
        |
/api/intelligence/journey
        |
MapAble manager agent
        |
Care | Transport | Jobs | Access | Moves | Foods | AbilityPay specialists
        |
typed, approved service tools
        |
existing MapAble services and Prisma repositories
        |
signed approval token + explicit participant confirmation
        |
/api/intelligence/approvals/transport
        |
existing createTransportTrip service
```

The manager agent remains responsible for the participant-facing response. Specialist agents provide domain analysis but cannot write to the database.

## Safety boundaries

- Tools are classified as `read`, `draft`, or `write`.
- The initial registry exposes read-only tools.
- Model output cannot create a trip.
- A signed, short-lived approval token contains the exact proposed action.
- The approval route validates the session, permission, token signature, expiry, user identity, and existing transport schema.
- The existing transport service performs the write and existing audit/event logic remains active.
- A standard non-AI transport form remains available.
- Participant profile data is read only after the user selects the profile option for that request.

Prohibited uses include automated support eligibility, clinical diagnosis, emotion recognition, disability severity scoring, autonomous employment rejection, unapproved bookings, unapproved payments, and unapproved sensitive disclosure.

## Environment variables

All values are server-side. Never prefix them with `NEXT_PUBLIC_`.

```env
OPENAI_API_KEY=
MAPABLE_AI_ENABLED=true
MAPABLE_AI_APPROVAL_SECRET=replace-with-a-long-random-secret
```

`MAPABLE_AI_APPROVAL_SECRET` is required for approval tokens. During migration it can fall back to `NEXTAUTH_SECRET`, but a dedicated secret is recommended.

When `OPENAI_API_KEY` is absent or `MAPABLE_AI_ENABLED=false`, the journey slice uses a deterministic explanation while retaining the same approval controls.

## First vertical slice

1. Participant opens `/ask`.
2. Participant supplies pickup and destination and may opt into accessibility-profile use.
3. `POST /api/intelligence/journey` reads the next calendar appointment.
4. MapAble generates advisory options and evidence.
5. The manager agent asks the Transport specialist for analysis and returns a structured explanation.
6. The UI clearly states that live availability has not been checked.
7. No database write occurs.
8. Participant presses **Confirm and create transport request**.
9. `POST /api/intelligence/approvals/transport` verifies the signed proposal and creates the request through the existing service.
10. Agent-run and audit records capture the workflow.

## Accessibility

The interface includes:

- programmatic labels;
- visible keyboard focus;
- 48px-class targets through existing large button sizing;
- status and error live regions;
- plain-language explanations;
- evidence and confidence disclosure;
- no pointer-only controls;
- a non-AI route for the same essential function.

Representative evaluation scenarios are stored in `intelligence/evaluation/scenarios.ts`.

## Expansion path

Future increments should add approved service tools without bypassing the registry:

- Care: support request and continuity summaries
- Jobs: inclusive matching and adjustment drafting
- Access: evidence-backed venue summaries
- Moves: clinician-approved plan coordination
- Foods: preference-aware ordering drafts
- AbilityPay: invoice and budget explanation

Write tools must remain outside direct model control and use explicit approval routes.

## Rollback

### Immediate operational rollback

Set:

```env
MAPABLE_AI_ENABLED=false
```

This disables model reasoning while retaining deterministic journey preparation and the existing transport flow.

### Disable the vertical slice

Remove `AccessibleJourneyAssistant` from `app/ask/AskPageClient.tsx`. Existing Copilot and standard transport forms continue operating.

### Full code rollback

Revert the Intelligence Fabric pull request. It introduces no Prisma migration and does not alter existing transport records or authentication models. Existing approval tokens expire after 15 minutes and become unusable after a secret rotation.
