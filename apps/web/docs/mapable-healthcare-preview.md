# MapAble Healthcare practice visit

The preview rehearses a participant-led telehealth visit in the canonical MapAble app. It uses a fictional speech pathology appointment. The web and Expo clients share the same state transitions for preparation, waiting, admission, participation and exit. The design uses browser entry, dedicated rooms and a clear waiting area as functional inspiration from [Coviu](https://www.coviu.com/en-au/company/about).

## Run the preview

From `apps/web`, install with the repository's pinned pnpm version. Start the web app with `MAPABLE_HEALTHCARE_PREVIEW_ENABLED=true pnpm dev` and open `/telehealth/preview`. The marketing page at `/telehealth` exposes a practice-visit link when the same flag is enabled.

For mobile, install the dependencies in `apps/mobile` and start Expo with `npm start`. Open **More → Open healthcare preview**. Native device builds and assistive technology checks are part of the pilot validation.

A participant can choose video, audio or text, try typing and AAC quick phrases, and decide whether to share access preferences in the simulation. Interpreter and support-person preferences and the callback action illustrate the user journey. They generate no requests. The web device check opens user-approved devices briefly and stops all streams. The consultation itself uses local text, an illustrative portrait and sample captions. Its chat and sharing authorisation are cleared on exit. The code keeps these choices and messages in memory and sends them to no service.

## Run the separate LiveKit lab

The lab is for software testing with sample data. It uses published test credentials from [LiveKit’s local server guide](https://docs.livekit.io/transport/self-hosting/local/). Bind both processes to loopback and run the web process in development mode. Use a separate terminal for each command.

```sh
livekit-server --dev --bind 127.0.0.1 --node-ip 127.0.0.1
```

```sh
cd apps/web
MAPABLE_HEALTHCARE_PREVIEW_ENABLED=true MAPABLE_HEALTHCARE_MEDIA_LAB_ENABLED=true pnpm exec next dev --hostname 127.0.0.1
```

Open `/telehealth/preview/media` via `http://127.0.0.1:3000`, create a room and paste the code into a second local tab. Camera and microphone publish only after a user action. There is also a typed data channel. The lab creates five-minute join JWTs with a random identity and camera, microphone and text permissions for that room. It requires a same-origin loopback request and refuses to issue tokens in production builds. The media lab is separate from MapAble's existing Virtual Care Hub and its video-provider selection.

## Enable Muse Spark in the local conversation coach

The **Help and alternatives** screen includes a conversation practice exercise on web and mobile. Without a credential it shows authored replies to three AAC-friendly sample phrases.

For the web development lab, place a Meta Model API key in `MODEL_API_KEY` in `apps/web/.env.local` and set `MAPABLE_HEALTHCARE_MUSE_ENABLED=true` with the practice-visit flag enabled. Bind Next.js to loopback as in the media lab command above. **Ask Muse Spark** then appears in the web coach. The React Native rehearsal uses the offline replies.

The coach uses the repository's OpenAI-compatible TypeScript SDK with [Meta's Chat Completions endpoint](https://dev.meta.ai/docs/protocols/chat-completions) and the Standard `muse-spark-1.3` model. A same-origin development endpoint accepts a bounded scenario identifier. It sends only an authored sample phrase and its approved reply options. The model selects an identifier and MapAble renders the corresponding authored reply. The coach falls back to its local sample if the provider is unavailable or returns an invalid selection. Successful selections are reused for the current development process.

The key stays server-side. Consult chat, voice, transcripts, access preferences, appointment details and clinical records stay outside this adapter. The hosted API is an optional part of the local development lab. Pricing and access are handled through the developer's Meta account. See [Meta Model API data commitments](https://dev.meta.ai/legal/commitments) for retention terms.

## Path to a supervised Australian pilot

| Owner                                   | Evidence required before use with real appointments                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Participant co-design and accessibility | Observe participants completing the entire journey using AAC, switch access, VoiceOver, TalkBack and a desktop screen reader. Check reflow, touch targets, focus, no timed responses, caption quality with atypical speech and the option to continue by text. Use [WCAG 2.2 AA](https://www.w3.org/TR/WCAG22/) as the web target.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Clinic operations                       | Demonstrate appointment-bound patient invites, authorised clinician admission, identity confirmation, access to agreed interpreter support and participant-controlled supporter entry and removal. Plan for no connection, dropout and follow-up using a named clinic contact and a confirmed alternative.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Privacy and engineering                 | Review applicable Commonwealth and state obligations, complete a privacy impact assessment, validate Australian hosting and subprocessors, and define purpose, retention, access and incident handling. Enforce per-appointment roles, token expiry and revocation. Verify E2EE for media and text as configured, including how captions or interpreters affect protection. Keep recording disabled until the clinic approves a separate consent process. See [OAIC health privacy guidance](https://www.oaic.gov.au/privacy/privacy-guidance-for-organisations-and-government-agencies/health-service-providers/guide-to-health-privacy) and the [Australian Digital Health Agency telehealth standards guide](https://www.digitalhealth.gov.au/healthcare-providers/initiatives-and-programs/digital-health-standards/digital-health-standards-guidelines/get-started/5-standards-for-systems-and-technologies/telehealth-services). |
| Clinical governance                     | Confirm when virtual care is suitable, assign accountable practitioners, test the service's escalation and complaints process, and keep any clinical records in the authorised clinical system. See [Ahpra on virtual care](https://ahpra.gov.au/Resources/Information-for-practitioners-who-provide-virtual-care.aspx).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |

An authorised clinical record or practice management integration is a separate delivery milestone. MapAble's public evidence and synthetic datasets do not enter that record.
